# 让练习转化成独立写作能力

2026-10-02，v1.3。适用于本项目的学术类 Task 1 和 Task 2。

## 设计判断

更快提升的前提是练习击中当前问题，并能在撤掉帮助后迁移到新题。项目应让学习者知道下一步练什么、为什么练、怎样核验结果。不能用题目覆盖量、阅读时间或自查通过次数推算雅思分数。

现有研究支持反馈、检索和间隔练习的方向，但没有证明本项目的完整流程是所有人的最优方法。下面的任务长度、间隔和进阶条件是可执行的产品选择，实际效果仍需要真实学习数据检验。

## 研究依据

| 依据 | 对训练的启发 | 适用边界 |
|---|---|---|
| [IELTS 官方写作评分标准](https://ielts.org/cdn/ielts-guides/ielts-writing-band-descriptors.pdf) | 同时检查任务回应或达成、组织衔接、词汇、语法。写作训练要围绕实际内容与语言质量。 | 官方没有固定四段、每段五句或每段必须写 For example 的要求。 |
| [2024 年写作反馈元分析](https://doi.org/10.1016/j.learninstruc.2024.101961) | 词句层面的反馈和内容组织层面的反馈，应服务相应目标；单靠纠正语言不能解决全部写作问题。 | 研究涉及不同语言背景与教学环境；自动反馈及自反馈的一些结果未达统计显著，不能假定 AI 批改或自查必然有效。 |
| [Lim 与 Renandya，2020 年书面纠错元分析](https://tesl-ej.org/wordpress/issues/volume24/ej95/ej95a3/) | 纠错有助于二语书面语法准确性，学习者水平会影响效果。把一类错误放回自己的新句中练习。 | 研究不证明只修语法就能提升整体 IELTS 分数，也不证明某一种反馈形式对所有人更好。 |
| [Kim 与 Webb，2022 年二语间隔练习元分析](https://doi.org/10.1111/lang.12479) | 分散练习，并在延迟后检验记忆。48 项实验、3,411 名参与者的综合结果支持间隔练习。 | 这不是针对 IELTS 整篇写作的处方。等间隔与递增间隔没有显示统计差异；不能宣称 1/3/7 天最优。 |
| [Dunlosky 等，2013 年学习技术综述](https://acs.ist.psu.edu/ist521/dunloskyRMNW13.pdf) | 给主动检索与分散练习更多位置。看懂之后，合上材料再写。 | 一般学习研究不等同于雅思提分试验。范文仍可用于讲解、对比和示范，关键是之后需要自己的输出。 |

由这些证据推导出的产品方案是：诊断 → 理解反馈 → 针对性尝试 → 撤掉帮助换题 → 完整答卷校验。这是设计推论，不能直接把研究中的效果量换算为雅思提分幅度。

## 已实现的训练流程

1. **从原稿找目标。** 优先使用 AI 精批给出的具体目标：问题、连续原句、影响原因、一个练习动作、三条检查标准。引用必须能在当前原稿中找到。缺字段或引用不匹配时使用旧反馈路径；规则模板提醒不自动成为能力缺陷。
2. **按问题决定输出规模。** 审题与立场、论证、衔接、词汇、语法、概括、图表关系、完整度共八类。词句问题练新句，内容问题练段落，完整度问题练整篇。自动分类只是建议，原题改写阶段可以调整。
3. **卡住时提供教学。** 每类练习内置原创对比例子，说明较弱写法、改进写法及原因。图表示例的假设数据明确标注，与当前题目分开。连续两次未通过的短练习缩小到一个步骤；完整答卷的最低要求保持不变。
4. **留下可复核的证据。** 自查通过需要逐项核对标准和摘出当前作答中的连续原句。解释或疑问可选。未完成的尝试也能保存，避免因写不完而失去学习记录。
5. **撤掉帮助换题。** 改写通过后隔 24 小时复测，短练习独立通过后依次隔 3、7 天。打开讲解或自报使用外部帮助会留记录；辅助练习不增加独立通过次数，次日换题。题目排除已记录诊断、作答和训练草稿，优先相同题型，Task 1 要有内置图表。
6. **进入完整答卷。** 连续三次独立换题自查通过后，次日安排另一道新题写完整篇。Task 1 至少 150 词，Task 2 至少 250 词。可开启 20/40 分钟计时，时间与草稿跨刷新恢复，提交时保存用时；超时也可保留作答。
7. **决定下一步。** 整篇独立自查通过后结束本轮目标；失败或使用帮助则回到针对性复测。首页先安排到期复测，再安排整篇验证；其后优先已开始的草稿、最近 30 天反复出现的同类问题、较早的未完成目标。

三次短练习通过只是进入整篇验证的产品条件。整篇自查通过仍是学生判断，不能据此称为官方认可的掌握或某个 Band 水平。计时记录只说明开启计时后的墙钟用时，不自动判断考场表现。

## 反馈与结果的可信度

- AI 引用核验只能证明引文来自原稿，不能证明诊断、解释或分数正确。保留原稿、反馈与用户调整，让结果可复核。
- 独立性来自产品内帮助记录、提交快照和用户自报。工具不能监控用户是否在其他软件看了资料。
- 提交原作答后查看讲解，不抹掉已经保存的独立表现；看完再改写则重新记录条件。重复点击自查不会重置同一作答的提交时间。
- 旧记录缺少独立性信息时标记未知，不补造证据，不计入新版独立通过统计。已保存的旧作文、草稿、分数和训练历史保持可读。
- 自查标准、证据原句和作答均进入现有 `iwc_` 数据备份。进度报告分别汇总两项任务的 AI 参考评分，排除规则分数，并包含练习证据。
- 在进度页可复制原题、诊断原稿与新作答，请老师独立复核。材料提醒评阅者不给片段估整篇分；Task 1 需要另附图表。

## 如何检验它是否有效

用定期的未练过的新题完整答卷作为主要结果，保留作答时间、帮助条件、任务类型与评阅来源。关注相同问题是否在新答卷里减少，以及内容发展和准确性是否持续改善。AI 参考评分按 Task 分开看，并定期用外部反馈校验。

如果独立复测长期失败，先查问题是否分错、解释是否足够具体、任务是否过难；如果短练习通过而整篇仍失败，检查整体组织、时间分配和跨段落使用。练习次数和自查通过次数用于发现这些问题，不能单独证明训练产生了提分。

## 本地验收

- `npm test`：核心逻辑、语料、学习状态、具体目标引用核验、证据与标准、独立性、间隔调度、失败缩小任务、整篇验证、旧记录、保存失败、缓存指纹。
- `python -X utf8 run_checks.py`：同一套门禁纳入 CI，并检查既有范文内容与引用一致性。
- `python -X utf8 build_site.py`：生成包含新讲解模块的离线站点。
- `npm run test:e2e`：实际浏览器验证诊断、改写、提示、复测、整篇、计时恢复、导出、旧流程和离线缓存。AI 场景使用受控测试响应，无真实付费请求。

功能测试验证流程和记录行为，不验证学习效果。当前没有真实学习实验或提分保证。

2026-10-02 验收结果：`npm test` 的 89 项基础测试通过，完整 Playwright 的 41 项浏览器测试通过；v1.3.0 离线站点构建成功，87 个资源进入预缓存。新增训练表单在 1280、1440、1600px 和 390px 检查换行及操作，复核了明暗主题、讲解阅读、Task 1 实际图片加载、计时恢复和 HTML 导出。截图保存在 `.impeccable/review/learning-*.png`，使用测试作答，不代表真实评分或学习效果。
