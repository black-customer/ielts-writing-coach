# 学习效率优化 · 2026-09-30

本文记录 v1.1 的实现。当前 v1.3 增加具体目标、对比讲解、独立性记录和整篇验证，最新流程与研究边界见 [训练策略说明](learning-strategy.md)。

## 判断与实现

原项目题库和示范内容丰富，但把反馈转成学生自己的新作答需要多次手动跳转，也没有验证隔天还能不能做到。因此本次优先完善「独立作答 → 反馈 → 短改写 → 间隔换题」的流程。

- 训练首页优先显示到期复测，其次是最近未改写的诊断；没有任务时推荐独立练习或导入已有作文。无需累计五篇诊断。
- 一份诊断保留一个优先目标。AI 有明确修复建议时采用其首项；仅离线扫描时标注为需要自查确认的规则提示，避免把启发式当定论。
- 改写保存原稿、作答和自查证据。自查通过后 24 小时换题；随后按 3 天、7 天复测。三次通过仅记录为自查巩固，不宣称获得考官认可或某一分数。
- 复测先保持 Task 类型，尽量保持题型，排除原题和已有成功作答的题。题目仍来自现有题库；推荐器没有声称能自动验证具体能力。失败时次日重做本题。
- 范文和审题课保留，默认折叠。独立初稿可对照，草稿在刷新与退出后恢复。
- Impeccable 的 distill 指南用于减少入口选择：今日下一步优先、各册覆盖量折叠、原功能仍可访问。

## 修复的学习阻碍

- 段落阶段 2–5 错用了数组索引 1–4，导致开头被评为第二段、最后一段为空。现改为 0–3，同时修复范文段落和讲解引用。
- 范文检索忽略了传入题干，可能总把第一篇作为同题范文。
- 草稿保存与恢复用了不同的 storage key；学习会话输入现在同步保存。
- 新手问答只答一题就前进到了结果页；现在完整答三题，并去掉由知识选择题推算雅思分数的措辞。
- AI 记录缺少原题和全文、重复保存使样本数膨胀；现在保存快照并对同篇同来源去重。
- 旧 AI 反馈可能混入下一篇复盘和错因卡；现在按题目、全文、Task 类型核对，独立 AI 精批也可入错因库。
- Task 1 的 TA 被转换成 TR；现在保留 TA，并拒绝缺项或超出范围的评分。
- 默认全勾选的自评改为需自己逐项核验。规则扫描不再用其隐藏的启发式分数宣布「最弱项」。
- AI 精批区分官方评分标准与教学模板，去掉旧校准误差保证。无图表数据时禁止生成虚构数字的小作文范文；已有内置范文继续可用。

## 依据与边界

IELTS 官方按任务回应/达成、组织衔接、词汇、语法四项评价写作，实际语言的准确与得体应优先于模板符合度：[官方说明](https://ielts.org/take-a-test/preparation-resources/writing-test-resources)。

检索练习配合反馈与迁移练习是本次流程设计的依据：[研究者整理的迁移练习指南](https://www.retrievalpractice.org/strategies/2018/5/18/transfer-guide)。1/3/7 天是本产品的可执行默认间隔，不是针对该用户测得的最优间隔，也不能据此保证提分幅度。

当前的改写验收是明确标注的自查。离线工具不能判断论证质量或核实图表数字；这些仍需要原图、人工反馈或具备正确上下文的 AI 评阅。没有采集或改动用户已有学习数据。

## 验收方法

- `npm test`：原有 51 项核心逻辑、9 项语料检查，以及新增学习状态、间隔调度、去重、题目匹配、段落映射、AI 分数验证等测试。
- `npm run test:e2e`：现有六条流程与新增诊断改写闭环、草稿恢复、段落点评、AI 快照绑定、新手三题和窄屏检查。AI 使用受控测试响应，不调用真实付费 API。
- `python build_site.py`：构建离线站点，`learning.js` 自动进入预缓存。版本提高到 1.1.0 以更新部署后的缓存。

可衡量的后续效果：每周看完成的针对性改写数、换题自查结果、相同错误在新作文中的复现情况，并结合完整限时作文反馈决定下周重点。当前尚无真实学习实验结果。
